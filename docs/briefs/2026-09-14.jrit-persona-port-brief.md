# jrit-persona: port arscontexta's persona-relevant core - brief

Date: 2026-09-14.
Stage: idea brief (loop-brainstorm output), ready for /loop-plan.
Tracker: no issue logged yet; insert token segment when created.

## Outcome

Jeremy can create a persona - a written character sheet of stance (role, expertise, viewpoint) and voice - in one conversation, and use that same persona file two ways: adopted by an agent for consistent behavior and voice across a project (e.g. an architecture reviewer), or applied by a skill as a lens (review-as, draft-for-audience).
Presupposition verdict: "port arscontexta" was the named action; the checked reality is that its value here is the persona-relevant 20% - the 4-axis voice framework (warmth / opinionatedness / formality / emotional awareness, with its signal tables, conflict rules, and personality-to-artifact transformation matrix), the conversational derivation method (infer the persona from a few dialogue turns rather than a form), the preset pack shape, and the runtime-manifest consumption pattern - so this is a selective port, not a port of the plugin.

## End artifact

First real deliverables this unblocks: an audience persona used to draft and review a real RIT deliverable for its actual reader, and a project-scoped architecture-reviewer persona giving consistent subagent review voice on a live repo.
Both are exercisable the day v1 ships, since the consumers are conversation-level with no downstream integration required.

## Done looks like

- `/plugin install jrit-persona` from this repo's marketplace, restart, and the four skills appear.
- `/jrit-persona:persona-new` - conversational creation of one persona (agent-voice kind or audience kind) in a single hybrid flow: describe it free-form, the skill extracts traits labeled stated / inferred / defaulted, and a confirm pass covers only the inferred and defaulted bins.
- Created personas land in the global library `~/.config/jrit/personas/` by default, or a project's `personas/` directory on request; a project persona shadowing a global name wins, and consumers state which file they resolved.
- `/jrit-persona:persona-craft` - produce a deliverable (writing, design, diagram) given one agent persona (voice) plus one audience persona (who it is for), both required.
- `/jrit-persona:persona-review` - check an existing artifact (prose, deliverable, plan) against a persona and return concrete misalignment callouts; runs the persona as a fresh-context lens, rubix-style, so the review does not inherit the caller's framing.
- `/jrit-persona:persona-spawn` - generate a Claude Code subagent whose system prompt encodes a chosen agent persona, written into the target project for consistent voice across its ongoing work.
- All four flows plus schema validation and name resolution covered by the eval suite, green.
- The plugin carries MIT attribution (NOTICE or README credit) for content adapted from arscontexta.

## Approach

Chosen: fresh plugin, selective port, under jrit-loop house conventions.
Port source pinned: github.com/agenticnotetaking/arscontexta at commit 2acfd5cc4473c4d06c46be63df748e77e00e2746 (2026-02-19); all file and line citations in this brief resolve against that commit, re-fetchable from GitHub if the local /tmp clone is lost.

Ported from arscontexta, as adapted method rather than code:

- The 4-axis voice framework from `reference/personality-layer.md`: warmth / opinionatedness / formality / emotional awareness, the signal-to-dimension tables, the conflict rules (explicit beats implicit; at most one clarifying question), the personality-to-artifact transformation matrix, and the "voice, not substance" invariant.
- The conversational derivation method, as a single hybrid flow: open free-form, extract traits with qualitative stated / inferred / defaulted labels, propose before generating, confirm pass on the weak bins only.
- The preset pack shape (a persona pack as config plus exemplars) and the runtime-manifest pattern (consuming skills read the persona file at step 0 instead of being forked per persona).

Left behind, deliberately: the 249-note methodology graph, the vault three-space architecture, the 16 note-processing skills, the unreconciled dual template mechanism, the 6-phase setup pipeline as machinery (Detection and kernel-primitive Validation are vault-specific), and the numeric confidence scoring (weighted signals, cumulative 1.5 resolution threshold, verified at `skills/setup/SKILL.md` lines 185-340).
The scoring machinery exists to decide when to stop interviewing across 8 interdependent dimensions feeding 15 generated files; a persona is one cheap, human-reviewed file, so qualitative bins at the propose step do the same epistemic work without arithmetic.

Decision supersession, recorded: the earlier "both, layered" creation answer (guided template fast path plus derivation deep path) is superseded by the single hybrid flow, accepted 2026-09-14.
Rationale: the hybrid degrades gracefully in both directions - a terse complete description makes the confirm pass trivial, a rambling one exercises full extraction - so one flow serves both users and the plugin ships one creation skill instead of two.

Alternatives considered:

- Fork-and-prune arscontexta - rejected: the 1713-line setup skill is vault-entangled and the pruning cost likely exceeds fresh-build cost.
- Adopt-and-extend zvoque/claude-personas - rejected: external moving foundation, agent-modes focus, no derivation depth or content lenses.

Dated ecosystem facts (searched 2026-09-14): zvoque/claude-personas, tommcfarlin/claude-code-persona-generator, and FortunaTerra's multi-persona review panel exist; none combine derivation-depth creation, one-format-two-uses, and audience/creator content lenses; zvoque's per-turn persona re-assertion hook is noted as a stealable mechanism for planning.

The persona sheet is stance plus voice: the 4 axes cover voice only; the stance layer (role, expertise, viewpoint, cares) is structured during planning.
One schema serves both kinds via a kind field, per the one-format decision.

Composition rule (ported "voice, not substance" invariant): personas carry stance and voice; skills carry methodology; global principles carry standing constraints.
A persona never overrides a rule - substance beats voice, explicit beats implicit.
persona-craft applies personas as in-session lenses over the craft skills that own build mechanics; it never spawns.
Spawned agents are derived renderings of a persona through the transformation matrix; the persona is the source of truth, so a stale agent is regenerated, never hand-forked.

Format invariant: a persona file is a declarative, role-agnostic sheet.
A rendering is a function of persona x role (creator, audience, reviewer, agent identity - an open set) x consumer, owned by the consumer via the transformation matrix - personas never embed prompts or roles.
The kind field is an affordance hint, not a role lock.
v1's commands hard-assign roles (craft: creator plus audience; review: reviewer; spawn: agent identity); future consumers and roles add rendering recipes without touching persona files.

Further durable invariants (possibility sweep, 2026-09-14):

- Persona names are stable identifiers - consumers and spawned agents reference by name, so a rename is a breaking change.
- Persona files are self-contained portable text - no absolute paths, nothing harness- or model-specific; a persona works pasted into any capable model.
- Sheets are compact by design - consumers load them at step 0, so size discipline is part of the format.
- Every sheet carries provenance metadata (author, owner, created date, last-validated date, derivation source) - the hook the parked learning and team-trust futures hang on.
- A persona is data carrying stance and voice only - never permissions, tool instructions, or executable directives; consumers treat persona text as untrusted input.

- [executed-check] Name resolution: a project persona shadowing a global one wins (test).
- [judgment] Created personas read as distinct and true to their sheet; reformulated toward marker assertions in the evals above, but whether a voice sounds right genuinely needs a human.
