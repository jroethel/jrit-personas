2. Architectural principles that emerged

Port the method, never the machinery
Kept: the 4-axis voice framework (reference/personality-layer.md), derivation-as-conversation, conflict rules, the transformation matrix. Left: the 249-note methodology graph, vault three-space architecture, 16 note skills, the numeric confidence scoring (weighted signals, 1.5 resolution threshold).
The scoring machinery exists to stop an interview across 8 dimensions feeding 15 generated files; a persona is one cheap human-reviewed file. Rigor machinery must match blast radius.
A persona file is a declarative, role-agnostic sheet
Rendering is a function of persona x role (creator, audience, reviewer, agent identity - open set) x consumer, owned by the consumer via the transformation matrix. Personas never embed prompts or roles; the kind field is an affordance hint, not a role lock.
Surfaced 2026-09-14 when Jeremy generalized "audience pack parallel to brand pack" to "creator is also parallel", exposing that the matrix as first written was one axis short.
Voice, not substance (composition rule)
Personas carry stance and voice; skills carry methodology; global principles carry standing constraints. A persona never overrides a rule - substance beats voice, explicit beats implicit. Provenance stack: harness, then global principles, then skill, then persona; spawned agents are derived renderings, regenerated, never hand-forked.
Durable invariants are how a lean v1 avoids costing future scale
Stable names as identifiers; self-contained portable text (model- and harness-agnostic); compact sheets (step-0 loading); provenance metadata (author, owner, created, last-validated, derivation source); trust boundary (stance and voice only, never permissions or tool instructions, treated as untrusted input).
Missed scale never comes from building too little in v1; it comes from format decisions that foreclose unmapped futures. Divergence feeds invariants, invariants constrain seam work, v1 stays thin.
Three qualitative bins replace numeric confidence
persona-new's single hybrid flow labels each extracted trait stated / inferred / defaulted; the confirm pass covers only the weak bins. Binary stated/not-stated loses the inferred middle and either ships wrong extractions silently or re-asks what was communicated.

3. Design-process learnings

Brainstorm from consumers backward, not from source material forward
The session's biggest miss: anchoring on arscontexta's creation-engine shape produced "creation + a thin apply" while Jeremy, thinking from usage backward, supplied the four-command surface, the two-persona composition (voice x audience), and the role axis.
Diagnosed on Jeremy's direct ask "what had you as the brainstormer miss these possibilities?"; root causes: source-forward anchoring, unary application model, convergence pressure applied during divergence, sweeping tools instead of the workflow behind them. Saved to persistent memory as brainstorm-from-consumers-backward.
The possibility sweep (4 moves) closes that gap structurally
Future-back pass, cross-product enumeration, consumer-backward walk, scale probes - run before convergence, output capped to parked items and durable invariants, banned from widening Done-looks-like. Filed as jrit-loop#17; dogfooded on this brief, yielding 4 invariants and 4 parked items.
Near-miss: a proposal quietly reversing a settled decision
Jeremy's four-command proposal said personas are "saved to your personal cross-project library", which would have silently dropped the settled global+project two-home answer. Flagged out loud; Jeremy kept global+project. Supersessions must be explicit decisions with dates - the brief records the one real supersession ("both, layered" replaced by the single hybrid flow, 2026-09-14).
Near-miss: verb collision in the command surface
persona-new (makes a persona) vs persona-create (makes content) would be misremembered constantly. Renamed; "draft" was rejected because deliverables span writing, design, and diagrams - persona-craft chosen, aligning with the future craft skillpack.
Adjudicating another session's proposal: agree only after an adversarial pass
Another session's hybrid persona-new recommendation was verified against disk (the 1.5 threshold claim checked in skills/setup/SKILL.md lines 185-340), agreed with in core, and amended twice: three-bin labels instead of binary, and the silent supersession of "both, layered" surfaced as an explicit call.
Fresh-context review finds what the author's chair cannot
The Rubix pass (Lens A impacted-professional, Lens B cold craft on Opus) found: the port's source of record in wipeable /tmp, an unverified eval-harness capability underwriting two [executed-check] criteria, missing MIT attribution, and the persona-as-injection-surface trust gap. None had surfaced inline.

7. Update: persona-seats session, 2026-10-08

What happened
A loop-drive run replaced the persona kind field with a required seats list, added optional ## As <seat> sections, defined jargon tolerance in writing, shipped the change-management-prosci persona, and added two doctypes to jrit-craft. Ten units, four waves, all gates green, nothing pushed.
Reading the result, Jeremy asked why seats was required at all when the sections are optional and 11 of 14 sheets say only [audience]. Reconstructing the rationale from the record led to the decision below: drop the list and derive seats from the body.

7a. Architectural principles that emerged

A persona is a person; any person can sit in any seat
Stance and Voice are all a consumer needs to write as, read as, or review as a persona. A ## As <seat> section adds to that when the persona sits in its seat; it never gates whether the persona may sit there.
The 2026-09-14 brief already said so: "The kind field is an affordance hint, not a role lock." The seats run turned the hint into a lock (craft, review, and spawn refuse "with no fallback") without anyone deciding to.
A label set by mechanical migration is not a judgment
Every seats: [audience] line came from sed over the old kind: audience. It therefore carried no information about richness, consent, or intended use, yet three skills treated it as permission.
Spawn is persistence, not a mode and not a gate
spawn writes .claude/agents/<name>.md with Stance and Voice embedded "for consistent voice across ongoing work". Every session can already run craft and review with any persona by name. Fresh-context reviewers (review, rubix-review Lens A, craft-write seat review) paste the persona file into a subagent and never call spawn, so spawnability was never a precondition for seating a persona.
"Blessed to be spoken as" is provenance and consent, not a seat
The two protections the seat label stood in for are richness (visible in derivation-source and last-validated) and consent to write in a real person's voice (parked as issue #7). seats: [creator] measured neither: jeremy-voice spawned with no confirmation while thin converted sheets carried the same label quality.
Check custody can live in the spec text
When a plan hands workers their own test files verbatim, the plan is the custody: a byte canon built from the pinned plan commit, compared by every validator before trusting a PASS. All 17 verbatim files came out byte-identical.

7b. Design-process learnings

Before changing a design, find the written rationale and check it against the record
Jeremy asked for the rationale before approving a change. The brief gave three reasons for the list; two argued for the sections, not the list, and the third (checker consistency rules) was the only thing the list actually did. That reading, not intuition, settled the call.
Surfaced 2026-10-08 answering "can you find rationale for the seats: list being explicit and required?"
Near-miss: an invariant can be violated by a plan that cites it
The seats brief inherited "one person, many seats" from the port brief and still hard-locked roles one layer down. Guard: when a brief replaces a field, re-read the invariants the old field carried and say which survive.
Near-miss: a required-ness inherited from the field being replaced
"At least one seat is required" was never argued; it was kind's required-ness carried over one-for-one. Replacing a field is the moment to re-decide its cardinality and whether it is required.
Reconstruct the user's past thinking from artifacts, then confirm, rather than agree with the recollection
Jeremy's reconstruction ("only spawn if spawnable, as a blessing") was close but the record showed the opposite design intent. Reporting the discrepancy plainly produced a better decision than confirming the memory would have.
Change a format before it ships, not after
0.2.0 was merged on persona-seats but not pushed when the question came up. A second breaking change before the push costs one migration; after it, two. The decision was taken at the cheap moment.

7e. Operational learnings

The receipt helper's done --ran runs under sh -c, which is dash on WSL
A bash-only acceptance (diff <(...)) is charged as a failed check and routed to review. Wrap every acceptance in bash /tmp/<run>/checks/uNN.sh. Worth a jrit-loop issue.
claude plugin validate --strict does not parse skill frontmatter
A SKILL.md description written as an unquoted scalar containing ": " passed validation and the repo's structure check, and only an Opus validator caught it. A YAML parse of every skills/*/SKILL.md frontmatter belongs in ci/structure-check.sh.
Opus validators caught what grep anchors cannot
Both single-criterion fails in the run (two sentences on a line in a doctype; the YAML scalar) were invisible to the plan's anchor tests. Prose and format contracts need a reader, not a grep.
~/repos/jrit is now itself a git repo
Nested-repo hazard: the harness's worktree isolation would snapshot the wrong repo, so every worker created its own worktree with git -C <repo> worktree add. jrit-craft worktrees must be siblings of jrit-personas because its tests resolve ../jrit-personas.
A four-backtick fence hides a block from a three-backtick extractor
The U04 unit block was fenced with four backticks because it contained three; the prompt extractor skipped it and nearly launched U04 with U05's brief. Extractors must match ^`{3,4}$.
Persona-seats eval ordering
craft-seat-refusal seeded personas that Task 3 migrated, so it depended on Task 3 as well as Task 1; the plan's dependency line said Task 1 only. Evals that seed shipped files depend on every task that edits those files.

8a. Architectural principles that emerged

Retiring a key means giving every rule that read it a new source of truth, not just deleting the read
Review's mode rule used to settle "review X against Y" from Y's declared seat. The plan deleted the seat and rewrote the line to ask whenever the request names no mode, so the skill began stopping at a question on the most common request. The fix settles the mode from the persona's cues: a ## As reviewer section means approver, a ## As audience section or any audience key means audience fit, a ## As creator section means voice fit, and only none or several cues ask.
Surfaced 2026-10-09 when review-misalignments scored 0.33 with two of three runs ending at "which mode?"; fixed in commit be57fbe.
A declared key with no reader is a false promise in the format doc
time-budget is documented as "read when the persona sits as audience", accepted by the checker, extracted by new, and read by nothing. Filed as issue #49 (wire it into craft and review as a length cue, or retire it).
Jeremy caught it during the H1 read: "what does time-budget actually do? what uses it, and how?"
Exact error strings pinned across repos are a contract, and should be treated as one
jrit-craft's two negative persona tests grep the exact message jrit-personas's checker prints. Any rewording there breaks tests in another repo; the loop review named it as mild Primitive Obsession and acceptable as a contract check.

8b. Design-process learnings

A static gate cannot see a "when to ask" regression; only a live eval whose prompt does not name the answer can
Every anchor test, the full ci/run-all.sh, and nine Opus validators were green across four waves while review had quietly started asking a question on every unnamed-mode request. The H2 case whose prompt names no mode was the only thing that caught it.
A grader that passes an empty output hides exactly this kind of regression
review-clean scored 1.00 while all three of its runs produced no review at all, because its grader only checks for false callouts. Filed as issue #50: a grader must fail when no deliverable was produced.
Haiku three-vote judges at threshold 1.0 flip on identical sound output; a sonnet judge settled it 18 of 18
After the fix, two with-runs that named all three planted misalignments verbatim still drew FAIL votes, and a no-plugin run with all three drew FAIL FAIL FAIL. Re-running the one case with --judge-model sonnet passed every vote. Same defect as MODEL-NOTES 2026-10-01 and issue #25.
Compile a whole-line replacement as the exact old line and the exact new line
Told to "replace the item X with Y", U06 swapped only the trailing phrase and kept X's parenthetical, which passes every grep anchor. The orchestrator's canon byte-compare and the validator caught it; one repair pass fixed it.
Near-miss: a decision already recorded in the plan was about to be asked again
The compile raised the README sed -i one-liner as an ASK before wave 3, though plan line 30 records Jeremy's 2026-10-08 decision to keep it. The pin review made it record-only. A decision in the plan's Global constraints is not re-asked.
Near-miss: a count in a prompt drifted from the directory it described
The U08 validator brief said "eight canon files" where six existed; the validator judged by the directory and flagged the wording. Cite the directory, never the number.
Near-miss: a memory note from the previous run read like an order not to run this one
The U02 worker saw the auto-memory line "do not re-run or push" from the persona-seats run and raised it as an open question instead of acting on it. Memory notes about a run must carry the run name and date so the next run on the same branch is not mistaken for a re-run.
Reviews that validators already gated can still earn their keep as advisory
The two-axis loop review found no spec gaps but surfaced three pre-existing drifts between docs/loop/conventions.md and how the loop skills actually name handoffs and journals, plus the never-applied archive rule.

8e. Operational learnings

claude plugin eval takes --case <glob> and --judge-model <model>; the default judge is haiku
One case re-runs for about a dollar. Results keep aggregate-result.json with each run's judged last message but no judge rationale; --keep-temp is the only way to keep traces.
Attribute an eval fail from the judged evidence, never from the score
Reading the three with-run outputs showed the skill fix had taken before the judge said otherwise; the score alone would have sent the fix back to the skill.
The sibling-worktree pattern held for a second run
Every worker created ~/repos/jrit/<repo>-uNN itself; no harness isolation; all pruned at the gates. The custody canon (56 files from the pinned plan commit) was byte-identical on every unit.
Journal entries are human-read: one sentence per line
The loop review flagged multi-sentence lines in the gate journal; the orchestrator reflowed it in the closing commit.
Two pre-existing defects to file
personas/architecture-reviewer.md has an unquoted colon in derivation-source, so its frontmatter fails a YAML parse that the grep-based checker cannot see. docs/loop/conventions.md names a filename grammar the loop skills do not use and an archive rule nobody has applied.
